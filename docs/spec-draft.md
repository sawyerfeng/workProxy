# macOS 网络规则代理切换工具

状态：需求与测试边界已由用户确认；目标仓库 sawyerfeng/workProxy。客户端控制方案尚未通过实机验证。

## Problem Statement

用户在不同 Wi-Fi 与有线网络之间切换时，需要手动调整 FlClash 或 Clash Verge 的系统代理和 TUN。忘记切换会影响联网；自动化又不能持续覆盖用户临时的手动操作。同名 Wi-Fi 还需要按地理位置区分。

## Solution

创建 macOS 菜单栏常驻工具，提供规则设置窗口。用户选择要控制的客户端，按 Wi-Fi 名称或指定有线接口配置规则，可叠加地址搜索得到的地点及半径。触发时按顺序执行第一条匹配规则，将代理设置为全部关闭、仅系统代理或仅 TUN。未匹配时维持现状，失败通知一次。

## User Stories

1. 作为用户，我希望在设置中选择 FlClash 或 Clash Verge，以便明确控制对象。
2. 作为用户，我希望按 Wi-Fi 名称设置规则，以便连接指定网络时自动切换。
3. 作为用户，我希望选择有线接口，以便主要连接变成该接口时自动切换。
4. 作为用户，我希望规则跟随系统主要物理网络，以便 Wi-Fi 和有线同时连接时行为明确。
5. 作为用户，我希望搜索地址、选择地点并设置半径，以便区分同名 Wi-Fi 所在环境。
6. 作为用户，我希望网络与地点条件同时满足才命中地点规则，以便避免误操作。
7. 作为用户，我希望选择全部关闭，以便停用目标客户端的系统代理与 TUN 而不退出客户端。
8. 作为用户，我希望选择仅系统代理，以便同时停用 TUN。
9. 作为用户，我希望选择仅 TUN，以便同时停用系统代理。
10. 作为用户，我希望拖动规则排序，以便第一条匹配规则具有优先权。
11. 作为用户，我希望新增地点规则默认位于同网络普通规则前，以便特定环境优先。
12. 作为用户，我希望没有规则匹配时保持状态且不提示，以便未知网络不被擅自处理。
13. 作为用户，我希望手动更改代理后不被持续纠正，以便临时操作有效。
14. 作为用户，我希望网络稳定 3 秒后才执行，以便过滤切换抖动。
15. 作为用户，我希望短于 3 秒的同网络断线重连不触发，以便保留手动状态。
16. 作为用户，我希望持续断线达到 3 秒后重连也重新匹配，以便同名网络换地点后更新规则。
17. 作为用户，我希望位置变化本身不触发，以便只在既定网络事件中操作。
18. 作为用户，我希望地点规则最多等待定位 5 秒，以便不无限等待。
19. 作为用户，我希望定位不可用时跳过地点规则，继续匹配后续规则，以便有明确降级行为。
20. 作为用户，我希望迟到的位置结果不补执行，以便不覆盖后续手动操作。
21. 作为用户，我希望应用启动时匹配当前网络一次，以便无需等待下一次切网。
22. 作为用户，我希望同网络唤醒不重复执行，网络改变才执行，以便保留手动状态。
23. 作为用户，我希望目标客户端未运行时不启动它，之后手动启动也不补执行，以便自动化不扩大操作范围。
24. 作为用户，我希望菜单栏显示运行和失败状态，以便理解当前情况。
25. 作为用户，我希望暂停自动切换时不改变代理，恢复时应用当前规则，以便临时停用自动化。
26. 作为用户，我希望默认登录启动且可关闭，以便日常无需手动启动工具。
27. 作为用户，我希望首次完成必要授权，以便日常切换不反复弹窗。
28. 作为用户，我希望执行失败时收到一次通知且不持续重试，以便及时发现异常。
29. 作为用户，我希望权限不足或客户端版本不支持时明确显示原因，以便不会把失败误认为成功。

## Implementation Decisions

- 第一版包含两款客户端、网络规则、地点条件、菜单栏与设置窗口；当前机器安装版本为 Clash Verge 2.5.8、FlClash 0.9.2。此版本信息仅用于原型验证起点，不代表已经兼容。
- 建议 Swift/SwiftUI 原生实现；系统最低支持版本待构建与测试矩阵确定。
- 单次处理链路：网络事件 → 获取主要物理连接 → 3 秒稳定判定 → 按需定位（最多 5 秒）→ 顺序匹配 → 检查客户端运行状态 → 设置目标状态 → 回读结果 → 状态展示及失败通知。
- 稳定计时在网络继续变化时重置。断线恰好 3 秒归入需重新匹配的一侧，以消除边界歧义。睡眠期间的监测空档不直接等同于网络断线；同网络唤醒遵循不重复执行规则。
- 地点条件为可选的网络条件附加项，不独立触发。规则失配不撤销历史动作；需要恢复状态时使用后续兜底规则。
- 定位必须检查时间戳和精度；无法可靠判断范围内外时按定位不可用处理。具体阈值待原型验证。
- macOS 的 Wi-Fi 名称读取也可能依赖定位权限。SSID 不可用时跳过依赖 SSID 的规则，不能误当作空名称命中；仍可识别的有线规则按正常路径处理。
- TUN 会改变路由和网络事件，必须识别底层物理连接、去重自身操作事件；不能将所有网络回调都当成切网。等待定位期间再切网，要作废旧任务。
- 客户端控制采用分客户端适配。Mihomo 内核接口不等于客户端系统代理控制接口；直接改系统代理可能与客户端代理守护冲突。优先做辅助功能读取菜单状态并操作客户端的验证，尚未确认它能稳定后台运行。
- 原型必须验证三个目标状态及实际系统状态、客户端状态的一致性；不得仅凭请求发送成功判定完成。操作一半失败必须显示部分失败/实际状态，不能假报完整成功。
- 不将修改运行中客户端配置文件或无状态触发快捷键作为已确认方案。辅助功能权限、客户端 TUN 权限与系统通知权限分开管理。
- 外部控制凭据如需保存，使用系统安全存储；不在日志或 issue 中记录密钥、订阅或精确私人位置。

## Testing Decisions

以下测试边界已由用户确认；不是已执行结果。

- 最高层主边界：输入网络/唤醒/启动/暂停事件及规则，通过可控时钟、位置结果、客户端状态，验证实际要求执行的代理目标与用户可见状态。覆盖整条规则执行流程，不为内部实现细节分别建立重复测试。
- 客户端适配独立做真实 macOS 验证：两款客户端的三种状态、重复设置同状态、客户端未运行、权限拒绝、部分失败以及客户端重载后状态一致性。
- 验证 2 秒/3 秒/4 秒断线、快速连续切网、Wi-Fi 与有线共存、TUN 自身导致的网络回调、IPv4/IPv6 路径差异、同网络和异网络唤醒。
- 验证定位超时、低精度、旧位置、迟到回调、等待时切网，以及定位权限拒绝导致 SSID 不可读的降级路径。
- 验证未知网络无动作无提示、手动操作不被覆盖、暂停无动作、恢复只处理一次、失败单次通知不循环重试。
- 当前目录仅有研究文档，无既有应用与测试惯例。首次真实开关测试会短暂影响联网，应在明确的测试窗口进行并记录前后状态。

## Out of Scope

- 节点选择、订阅管理、自建代理内核、流量规则编辑。
- 自动启动未运行的客户端、同时控制两款客户端、位置变化单独触发。
- 持续强制维持代理状态、后台无限重试、未知网络弹窗。
- 按 BSSID 识别特定 AP、按地点自动识别同一有线网卡的不同网络（可通过已选地点条件区分）。
- 承诺所有客户端版本兼容，或停用其他软件、终端环境变量和应用自定义代理。
