01 / 安装与权限

  1. 从发布页下载 workProxy-0.2.0-macos-arm64.dmg，将 workProxy.app 拖入“应用程序”。当前安装包适用于 M 系列 Mac，系统要求 macOS 13 或更高版本。
  2. 启动 workProxy，允许定位权限。macOS 读取 Wi-Fi 名称也需要定位权限；不用地点条件时，同样可能需要授权。系统定位服务也应处于开启状态。
  3. 通知权限可选，用于执行失败提醒。登录启动可在“设置”中开启。

当前安装包使用临时签名，尚未经过 Apple 公证。若系统提示无法验证开发者，先核对下载来源和发布说明；确认后，按 macOS 的“隐私与安全性”提示处理。不要全局关闭系统安全保护。

02 / 配置代理地址

先启动 FlClash、Clash Verge Rev 或你已有的代理客户端，确认客户端本身能正常联网。workProxy 不提供节点、订阅或代理内核。

  1. 在代理客户端中找到 Mixed / 混合端口。workProxy 会将同一地址和端口写入 HTTP、HTTPS、SOCKS 系统代理，优先使用同时支持这些连接方式的混合端口。
  2. 打开 workProxy 右上角齿轮 → 代理地址 → 修改。
  3. 主机填写 127.0.0.1，端口填写客户端的实际混合端口，例如 7897 或 7890。主机框里不用加 http://。
  4. 保存地址，确认显示“可连接”。只有这个步骤不需要 TUN 联动，也不需要控制器密钥。

这里填的是流量经过的代理端口，不是控制器端口。只想按网络切换系统代理，可以直接进入下一步。

03 / 创建网络规则

  1. 在主窗口点击 ＋。能识别当前网络时，会自动带入它；需要其他 Wi-Fi 或有线接口时，点击“更换网络”。Wi-Fi 名称无法读取时，可以从列表选择或手动输入。
  2. 选择 开启系统代理 或 关闭系统代理。例如公司网络关闭，家庭 Wi-Fi 开启。
  3. 需要区分同名 Wi-Fi 时，打开 限定生效地点（可选），搜索并选中地址，再设置范围。只输入地址但没有选中结果，不能保存地点规则。
  4. 点击 保存规则。规则默认启用；保存不会立即执行，下一次网络事件会匹配。需要立即验证时，在顶部“…”运行详情中点击“立即应用”，并确认自动切换已开启。

规则从上到下匹配，使用第一条符合条件的已启用规则。把带地点条件的具体规则放在同网络的普通规则前面；可拖动调整优先级，双击编辑，右键复制、移动或删除。

网络变化稳定 3 秒后再执行；没有匹配规则时保持现状。位置变化本身不会单独触发切换。

04 / Clash“控制台”到底填什么？

Clash 网页面板、Mihomo 控制器和代理端口是三件事。workProxy 通过本机 HTTP 控制器 API切换 TUN，不需要你安装或打开网页面板。

三个地址怎么区分
你看到的内容示例在 workProxy 填哪里
Mixed / 混合代理端口127.0.0.1:7897设置 → 代理地址，主机和端口分开填
外部控制器 / External Controllerhttp://127.0.0.1:9090设置 → Clash / Mihomo 联动 → HTTP 控制器地址
网页控制面板 / Dashboardhttp://127.0.0.1:9090/ui/ 或独立网页面板的网址不填。去掉网页路径，使用客户端提供的 API 地址

workProxy 0.2.0 仅接受 http://127.0.0.1:端口、http://localhost:端口 或本机 IPv6 回环地址。不支持远程 IP、HTTPS、WebSocket、Unix Socket / Pipe，也不能带 /ui/、/configs 等路径。控制器端口可能是 9090、9097 或其他值，不能靠猜。

在 FlClash 中准备控制器

  1. 打开 FlClash 的配置 / 覆写设置，找到 外部控制器（External Controller）。不同版本的入口或措辞可能有差异，以“外部控制器”为搜索关键词。
  2. 开启 HTTP 外部控制器，保留本机回环监听地址，记录实际端口。客户端显示 127.0.0.1:9090 时，在 workProxy 中写成 http://127.0.0.1:9090。
  3. 若客户端设置了 secret / 访问密钥，复制它；未设置密钥时，workProxy 的密钥框可以留空。不要填节点密码或订阅链接。
  4. 在 FlClash 中完成 TUN 所需的系统授权，确认客户端能够手动开启、关闭 TUN。workProxy 不会替客户端安装服务或绕过系统授权。

FlClash 可能用覆写项生成运行配置。优先使用客户端提供的设置，不要只改会被订阅更新或重启覆盖的临时配置文件。可以对照 FlClash 官方项目确认你所用版本的入口。

在 Clash Verge Rev 中准备控制器

  1. 打开 设置 → Clash 设置 → 外部控制，开启外部控制器。入口名称以当前客户端版本为准。
  2. 记录 外部控制器监听地址和 API 访问密钥。监听地址应为本机地址；复制后，在 workProxy 的控制器地址前补上 http://。
  3. 将 API 密钥原样填入 workProxy，不要加 Bearer 前缀，也不要把密钥拼到地址里。
  4. 按客户端要求启用服务模式 / 授权 TUN，先确认在 Clash Verge Rev 内能手动控制 TUN，再测试联动。

Clash Verge Rev 自己的界面能操作内核，不代表 HTTP 控制器已开启。workProxy 使用 Mihomo API；Clash Verge Rev 的完整联动尚未做本项目实机验证，具体入口与限制请同时参考客户端官方文档。

直接维护 Mihomo YAML 时怎么写？

在当前生效的本地配置或客户端支持的覆写中设置以下字段。保留原来的其他配置，不要用这两行替换整份文件。

external-controller: 127.0.0.1:9090
secret: "REPLACE_WITH_YOUR_OWN_RANDOM_SECRET"

将示例 secret 替换成自己的长随机密钥，并按客户端要求重载。这里只需要本机访问，不必开放局域网监听。字段含义见 Mihomo 官方配置说明。

最后，在 workProxy 中填写

  1. 齿轮 → Clash / Mihomo 联动，打开 系统代理与 TUN 同步开关。
  2. 填入完整的本机 HTTP 控制器地址和原样复制的 控制器密钥。
  3. 点击 测试连接。成功时会显示 TUN 当前已开启或已关闭；这个测试只读取状态，不会切换 TUN。
  4. 点击 保存联动设置。测试成功不等于已保存；保存也不会立即切换。

启用联动后，主窗口、菜单栏的手动开关和规则动作都会同步开关系统代理与 TUN。未启用联动时，只切换系统代理，其他工具的 TUN 状态不会因此改变。

控制器密钥保存在仅当前用户可读的本机设置文件中，当前未使用钥匙串。不要把密钥、订阅链接或完整设置文件贴到截图和公开 issue。若客户端还启用了“系统代理守护”等持续接管功能，请检查是否会覆盖 workProxy 的设置。

05 / 测试与排错

第一次配置完，先测试控制器连接，再验证实际开关。手动点击“代理”或“直连”会暂停自动规则；验证结束后，点击“恢复自动”或打开自动切换，重新匹配当前网络。

遇到问题先查这里
现象先检查什么
代理地址“不可连接”客户端内核是否正在运行，混合端口是否填对；不要把 9090 等控制器端口填进代理地址。
控制器连接被拒绝 / 超时HTTP 外部控制是否开启，客户端是否运行，监听端口是否实际生效。客户端的 Socket / Pipe 连接不能代替 HTTP API。
HTTP 401 / 403API 密钥是否与客户端一致，是否误填了订阅或节点密码，是否多了 Bearer 前缀、空格或换行。
HTTP 404 / 控制器响应无效是否填成了代理端口、网页面板或带路径的网址；确认这是支持 GET /configs 的 Mihomo HTTP API。
测试成功，但 TUN 开不起来“测试连接”只读状态。先在客户端手动验证 TUN 权限、服务和驱动，再保存联动并触发一次实际动作。
系统代理已更新，但 TUN 切换未确认这是部分失败。系统代理和 TUN 的修改不是原子操作；检查客户端当前实际状态、控制器连接和 TUN 权限。
Wi-Fi 名称读不到检查系统定位服务，以及 workProxy 的定位授权；也可先手动输入 SSID。不能保存空的网络条件。
规则保存了却没有执行保存不会立即切换。检查自动切换、规则启用状态和优先级；可从“…”运行详情中立即应用。
关闭系统代理后流量仍经过代理检查未联动的 TUN、PAC、自动代理发现、应用自定义代理及其他客户端。workProxy 不会关闭所有这些独立设置。

06 / 更新与日常使用

  • 更新：0.2.0 默认每 6 小时检查正式版本。发现新版本后会提醒，确认后下载、验证签名、安装并重启。也可以从 workProxy 菜单 →“检查更新…”或设置 →“软件更新”手动检查。
  • 从 0.1.0 升级：需要先手动安装一次 0.2.0，后续可在应用内更新。请从可写的“应用程序”文件夹运行，而不是直接从只读 DMG 中运行。
  • 暂停：只暂停自动匹配，不改变当前代理。恢复自动时会立即重新匹配当前网络。
  • 外观：设置 →“外观”，选择浅色、深色或自动切换；自动切换会跟随 macOS 系统外观。
  • 备份：配置位于 ~/Library/Application Support/workProxy/settings.json，包含规则、地点及可能存在的控制器密钥。备份时当作私人文件保管。

需要反馈问题时，请附版本、客户端名称、复现步骤和脱敏后的错误信息。不要附密钥或精确私人地址。
