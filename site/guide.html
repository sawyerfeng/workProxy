建议先配通基础的系统代理自动切换；如果你平时还会用到 TUN 模式，再接着配置 Clash 控制器联动。

01 / 安装与权限

  1. 前往 GitHub Releases 发布页下载 workProxy-0.2.1-macos-arm64.dmg，打开后把 workProxy.app 拖进“应用程序”文件夹（支持搭载 Apple 芯片的 Mac，系统需 macOS 13 及以上）。
  2. 首次启动 workProxy 时，请按提示允许定位权限。在 macOS 上，读取当前连接的 Wi-Fi 名称必须具备定位权限——因此即使你不添加地点条件，只要使用 Wi-Fi 规则就需要开启它，同时请确保系统总体的“定位服务”处于开启状态。
  3. 通知权限可按需开启，用于在切换执行失败时发送提醒；如果需要开机自动运行，可在“设置”中勾选登录时启动。

当前安装包使用本地临时签名打包，尚未经过 Apple 公证。首次打开若提示“无法验证开发者”，请先核对安装包是否来自官方发布页；确认无误后，前往 macOS“系统设置 → 隐私与安全性”按提示允许打开即可，无需关闭系统整体的安全保护。

02 / 配置代理地址

开始之前，请先启动 FlClash、Clash Verge Rev 或你常用的代理客户端，确认客户端本身已经能正常代理上网。workProxy 只负责控制开关，不内置节点、订阅或代理内核。

  1. 在你的代理客户端里查看 Mixed（混合）端口。由于 workProxy 会把同一组地址和端口同时写入系统的 HTTP、HTTPS 与 SOCKS 代理，建议优先使用同时支持这几种协议的混合端口。
  2. 点击 workProxy 主窗口右上角的齿轮图标，打开 设置 → 代理地址 → 修改。
  3. 主机填写 127.0.0.1（无需填写 http://），端口填写客户端实际的混合端口，常见如 7897 或 7890。
  4. 点击保存，确认状态变为 “可连接”。

注意：这里填的是日常网络流量经过的代理端口，而不是外部控制器端口。如果你平时只用系统代理、不开 TUN 模式，配完这一步就可以直接去创建规则了，无需配置控制器密钥。

03 / 创建网络规则

  1. 在主窗口点击右上角的 ＋。如果当前已连接可识别的网络，界面会自动填入；想为其他 Wi-Fi 或有线网卡创建规则，点击“更换网络”即可切换（读不到 Wi-Fi 名称时，也可从历史列表选择或手动输入）。
  2. 选择连上该网络后的动作：开启系统代理 或 关闭系统代理。比如把公司网络设为关闭代理，把家庭 Wi-Fi 设为开启代理。
  3. 如果遇到不同地方的 Wi-Fi 恰好同名，可以打开 限定生效地点（可选），搜索地址并从候选结果中点选确认，再设置生效半径。注意：只输入文字而未选中搜索结果时，无法保存地点条件。
  4. 点击 保存规则。新规则默认启用；保存操作本身不会立刻改动当前代理，会在下次切网时自动生效。如果你想马上验证效果，可以点开主窗口顶部的“…”运行详情，点击“立即应用”，并确认“自动切换”处于开启状态。

规则按列表从上到下依次匹配，命中第一条已启用的规则即执行。建议把带地点的细分规则排在同网络普通规则前面；列表支持直接拖动调整优先级、双击编辑，或右键进行复制、移动与删除。

检测到网络切换或断线时，workProxy 会先立即关闭代理，等新连接确认后再按规则决定是否开启，不再固定等待 3 秒。连上没有匹配规则的新网络会默认保持关闭，同网络断线重连也会重新匹配；而在应用刚启动或点击“恢复自动”时若未命中规则，则保持当前状态不变。单纯移动地理位置本身不会单独触发切换。

04 / Clash“控制台”到底填什么？

很多人容易把“网页面板”“Mihomo 外部控制器”和“代理端口”混在一起。其实它们各管各的：workProxy 是通过本机 HTTP 控制器接口发送指令来开关 TUN 的，并不需要你安装或打开任何网页面板。

三种常见地址对照表
你在客户端看到的名称常见示例在 workProxy 里填哪里
Mixed / 混合代理端口127.0.0.1:7897设置 → 代理地址（主机与端口分开填）
外部控制器 / External Controllerhttp://127.0.0.1:9090设置 → Clash / Mihomo 联动 → HTTP 控制器地址
网页控制面板 / Dashboardhttp://127.0.0.1:9090/ui/ 或在线面板网址不要填。请去掉 /ui/ 等路径，只填上面的控制器根地址

出于安全考虑，workProxy 仅接受 http://127.0.0.1:端口、http://localhost:端口 或本机 IPv6 回环地址，不支持局域网/远程 IP、HTTPS、WebSocket 或 Unix Socket / Pipe，地址末尾也不能带 /ui/、/configs 等路径。不同客户端默认端口可能是 9090、9097 或随机端口，请务必到客户端设置中查看确认。

在 FlClash 中开启控制器

  1. 打开 FlClash 的配置或覆写设置，搜索并找到 外部控制器（External Controller）（不同版本菜单位置可能略有差异）。
  2. 启用 HTTP 外部控制器，保持本机回环监听地址并记下实际端口。例如客户端显示 127.0.0.1:9090，在 workProxy 里请完整写成 http://127.0.0.1:9090。
  3. 如果客户端设置了 secret（访问密钥），将其原样复制出来；若未设置密钥，workProxy 中的密钥栏留空即可。注意不要误填成订阅链接或节点密码。
  4. 先在 FlClash 内完成 TUN 所需的系统权限授权，手动试开关一次 TUN 确认本身可用——workProxy 不会代替客户端安装后台服务或获取系统特权。

提示：FlClash 常通过“覆写”生成运行配置，建议直接在客户端界面中修改对应选项，避免直接改底层临时文件导致重启或更新订阅后被覆盖。具体入口可参考 FlClash 官方仓库说明。

在 Clash Verge Rev 中开启控制器

  1. 打开客户端的 设置 → Clash 设置 → 外部控制（具体名称以当前客户端版本为准），确认开启外部控制器。
  2. 记下 外部控制器监听地址 和 API 访问密钥。监听地址应为本机回环地址，填入 workProxy 时记得在前面补上 http://。
  3. 将 API 密钥原样粘贴到 workProxy 的密钥框中，不要加 Bearer 前缀，也不要拼进网址里。
  4. 按客户端指引启用服务模式或完成 TUN 授权，先在 Clash Verge Rev 界面里确认能正常手动开关 TUN，再来配置联动。

注意：Clash Verge Rev 自身界面能切换 TUN，并不代表 HTTP 外部控制器一定处于开启状态。workProxy 通过通用 Mihomo HTTP API 通信，目前尚未在 Clash Verge Rev 上完成全部真机场景实测，详情可结合 Clash Verge Rev 官方文档核对。

如果你直接手写维护 Mihomo YAML 配置文件，该怎么加？

在你当前生效的配置文件或客户端覆写配置中补充以下两行即可（请保留原有其他配置，不要整份替换）：

external-controller: 127.0.0.1:9090
secret: "REPLACE_WITH_YOUR_OWN_RANDOM_SECRET"

请把示例中的密钥替换为你自己生成的长随机字符串，保存后在客户端重载配置。联动只需本机通信，切勿监听公网或局域网地址。更多参数说明可参考 Mihomo 官方文档。

最后，回到 workProxy 完成接入

  1. 点击右上角齿轮 → Clash / Mihomo 联动，打开 系统代理与 TUN 同步开关。
  2. 填入完整的本机 HTTP 控制器地址 和原样复制的 控制器密钥。
  3. 点击 测试连接。连接成功后会显示当前读取到的 TUN 开启/关闭状态（测试操作只读状态，不会改动当前 TUN）。
  4. 确认无误后点击 保存联动设置。注意：仅点“测试连接”不会自动保存，保存后也不会立刻触发切换。

开启联动后，无论是规则自动触发，还是你在主窗口、菜单栏手动切换，都会一并开关系统代理与 TUN；未开启联动时则只改系统代理，不会碰客户端的 TUN 状态。同时建议关掉客户端自带的“系统代理守护”功能，免得两边互相覆盖。

控制器密钥目前以明文保存在仅当前用户可读写的本地配置文件中，暂未接入钥匙串。截图交流或提交 Issue 时，请注意不要暴露密钥、订阅地址或完整的配置文件。

05 / 测试与排错

首次配好后，建议先点“测试连接”确认通信正常，再手动点一下“代理”和“直连”试试实际切换效果。手动切换会暂时挂起自动规则；测试完毕后，点一下“恢复自动”即可回到按网络自动匹配的状态。

常见问题速查表
遇到的现象排查方向
代理地址显示“不可连接”确认代理客户端内核已启动，且混合端口填写正确；注意不要把 9090 等控制器端口填到了“代理地址”里。
控制器连接被拒绝或超时检查客户端是否已运行、HTTP 外部控制器是否开启、端口是否一致。客户端内部的 Socket / Pipe 控制方式不能替代 HTTP 接口。
提示 HTTP 401 / 403核对控制器密钥是否与客户端完全一致，排查是否误填了节点密码，或不小心多带了 Bearer 前缀、空格与换行。
提示 HTTP 404 或响应无效检查是否误填成了混合代理端口、网页面板地址或带了 /ui 等路径；这里需要的是支持 GET /configs 的根地址。
测试连接成功，但实际开不了 TUN“测试连接”只负责读取状态。请先在代理客户端里手动开关一次 TUN，确认服务模式、驱动和系统授权均已就绪。
提示“系统代理已更新，但 TUN 切换未确认”说明系统代理已改好，但 TUN 那一步未确认生效。两步操作并非绑定回滚，请检查客户端实际状态、控制器连接与 TUN 权限。
无法读取当前 Wi-Fi 名称检查 macOS 系统总体的定位服务是否开启，以及是否已授权给 workProxy；也可以先在规则里手动输入 Wi-Fi 名称。
保存了规则，但代理没变保存规则不会立刻触发切换。请检查“自动切换”是否开启、规则是否启用及排序优先级，也可在顶部“…”运行详情里点“立即应用”。
关了系统代理，流量却还在走代理排查是否有未接入联动的 TUN、浏览器代理插件、PAC / 自动发现，或某款软件自带的独立代理设置。workProxy 不会接管这些外部配置。

06 / 更新与日常使用

  • 应用内更新：应用默认每 6 小时自动检查一次正式版更新，发现新版时会弹窗展示说明；确认后会自动下载、校验签名、替换应用并重启。你也可以随时在菜单栏 workProxy → 检查更新… 或 设置 → 软件更新 中手动检查，或关闭自动检查。
  • 从 0.1.0 升级：0.1.0 尚未内置自动更新组件，请先手动下载一次最新版 DMG，将应用拖入可写的“应用程序”文件夹覆盖旧版（请勿直接在只读的 DMG 窗口内双击运行），后续版本即可直接在应用内更新。
  • 临时暂停：点击“暂停”只会挂起自动规则，不会改动当前的代理状态；点击“恢复自动”则会立刻按当前网络重新匹配一次。
  • 界面外观：支持在 设置 → 外观 中选择浅色、深色或跟随 macOS 系统自动切换。
  • 配置备份：所有设置保存在 ~/Library/Application Support/workProxy/settings.json，内含规则、地点坐标及可能填写的控制器密钥，备份时请妥善保管，切勿公开分享。

使用中如果遇到问题，欢迎前往 GitHub 提交 Issue，附上你的 macOS 版本、代理客户端名称及版本、复现步骤和脱敏后的报错提示（请勿贴出密钥或私人详细住址）。
